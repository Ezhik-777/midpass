# Опционально: оптимизация локального pre-check (Step 0 в confirm-queue).
# Если RENEWAL_INTERVAL_HOURS задан — pre-check разрешает попытку только
# когда с момента последнего успешного подтверждения прошло не меньше
# указанного числа часов. Это экономит запросы к серверу и капчи между
# окнами подтверждения. Если параметр пуст или не задан — pre-check
# всегда разрешает попытку (поведение по умолчанию).
# Окно подтверждения на новом API плавает: сервер открывает его примерно
# через 24-30 часов после прошлого подтверждения (не в фиксированное время
# суток). Поэтому RENEWAL_INTERVAL_HOURS=25 — не дёргаемся первые 25ч
# (экономим капчу), затем проверяем каждый час. Если параметр пуст/не задан —
# код по умолчанию pre-check выключает (проверяет каждый тик).
# RENEWAL_INTERVAL_HOURS=25
#
# После ответа сервера canConfirm:false бот фиксирует момент и в течение
# этого окна (минут) не делает повторных попыток. Default 60.
# NEGATIVE_PROBE_COOLDOWN_MINUTES=60
#
# Sanity-страховка: с этого часа форсим попытку каждый тик, игнорируя
# кулдаун (на случай задержки окна). Code default 28 — уверенно ловит окно,
# открывающееся ближе к 30ч.
